# Migrating to Codex v0.4.1

`v0.4.1` aligns canonicalization with `@ui8kit/contract` commit `d05ee75`.
Do not tag this module until the contract owner confirms the release.

## Term and settings

- `canonical.CanonicalizeTerm` / `canonical.TermDigest` implement profile
  `codex-term/v1`. `count` is dropped and is not part of the canonical form.
- `canonical.CanonicalizeSettings` / `canonical.SettingsDigest` implement
  profile `codex-settings/v1` (prefix `codex-settings/v1:sha256:`).
- Both use the entry rules: strict parser, closed keys, safe integers, dates
  as `YYYY-MM-DDTHH:MM:SSZ`, empty optionals omitted only at the top level.
- `content.Settings` is `SettingsV04`: a separate record type, key
  `(id, locale)`. `content.SiteLocale` returns `settings.language`, or `"en"`
  when there are no settings.
- Official vectors: `conformance/contract/fixtures/vectors/term.json` and
  `settings.json`. `count` is accepted then dropped; an unsafe integer in
  `count` is still `canonical.unsafe_integer`. Settings `id` uses the same
  opaque-id pattern as entries.

## Manifest v2

- Wire identity of a JSON document is `canonical.CanonicalizeManifest` /
  `canonical.ManifestDigest` (`codex-manifest/v2:sha256:`).
- v2 is JCS of the **full** manifest with source array order kept. No array
  is sorted (resources, taxonomies, capabilities, relations, allowed_targets).
- Nested empty values (`"policy": {}`, `"fields": []`) are kept. Empty
  optionals are omitted only at the top level.
- `Manifest.Digest()` v1 is unchanged (Go `encoding/json` of `Canonical()`,
  which still sorts set-like collections). The
  `example.manifest.canonical.json` fixture stays v1.
- `Manifest.DigestV2()` no longer calls `Canonical()`. The official vectors
  live at `conformance/contract/fixtures/vectors/manifest.json`.

## Generic JCS

- `canonical.JCS` serializes JSON-native values as RFC 8785. HTTP servers
  must not use `encoding/json` for envelopes, discovery, or error bodies.
  `canonical.Format` remains an alias.
