# Migrating to Codex v0.4

`v0.4.0` is a pre-v1 contract correction to match `@ui8kit/contract` 0.2.0
(commit `8299fee`). Types, JSON names, and the entry canonical profile change.

Do not treat this module as released until the contract owner confirms the
official vectors. This repository does not tag `v0.4.0` from this change.

## Records

- The record key is `(id, locale)`. Translations are separate records that
  share `id` and differ in `locale`.
- `locale` is a required BCP 47 tag (`ru`, `en-US`). Region case is preserved.
- Chrome (`slug`, `title`, `content`, `excerpt`) is a plain string. Chrome is
  always localized; `Field.Localized` is not used for those ids.
- `LocalizedText`, `Entry.Locales`, and `LocaleDocument` are removed.
- `status` adds `pending`.
- New optional fields: `order`, `pinned`, `format`, `discussion`, `origin`.
- `id` is opaque ASCII `^[A-Za-z0-9][A-Za-z0-9._:-]{0,127}$`. Integer platform
  keys become `<kind>-<n>`. The pattern applies only to `id`, not to `*_id`.
- Term and taxonomy labels are strings plus `locale`. Terms require
  `created_at` and `updated_at`.
- Revisions bind to `(entry_id, locale)` and the snapshot locale must match.

## Fields and money

- `Field.Localized` means translatable. Non-localized fields must be equal
  across locale records of the same `id` after canonicalization
  (`entry.localized_mismatch`).
- Money is a safe integer in minor units plus one ISO 4217 `currency` per
  record. Negatives are allowed. There is no `min` rule.
- Integers with `|n| > 2^53-1` are `canonical.unsafe_integer`.
- Unknown non-empty field-rule names are `schema.field.rule_unknown`.

## Canonical form

Profile `codex-entry/v1` is RFC 8785 JCS over the public projection:

- drop `metadata.*` with `private: true`;
- omit optional top-level `null` / `""` / `[]` / `{}` (do not touch
  `metadata.<k>.value`);
- dates `YYYY-MM-DDTHH:MM:SSZ`; offsets convert to Z; `.000` is dropped;
  non-zero fractional seconds are `canonical.fractional_seconds`;
- `terms` sorted by `(taxonomy, term_id)` in Unicode code-point order;
  `origin` keeps order;
- numbers follow ECMAScript `Number.prototype.toString` (`1e21` → `1e+21`,
  `-0` → `0`);
- strings follow JCS (no HTML escaping of `<>&`, no `\u` for U+2028/U+2029);
- unknown fields and duplicate keys are errors;
- `order: 0` and `pinned: false` are kept;
- Entry v0.4 has no `sensitive` field, so the profile removes nothing on that
  basis (`Resource.PublicProjection` still strips schema-sensitive fields).

Digest: `codex-entry/v1:sha256:` plus hex(sha256(UTF-8 bytes)).

Manifest identity: `Manifest.Digest` remains `codex-manifest/v1` (Go
`encoding/json` of `Canonical()`). `Manifest.DigestV2` is
`codex-manifest/v2:sha256:` over JCS of `Canonical()`.

Go `encoding/json` is not used for canonical output. The implementation is a
local RFC 8785 port of `@ui8kit/contract` `src/canonical.ts` at `8299fee`.

## Migrator

`migrate.EntryJSON` and `migrate.TaxonomyJSON` convert v0.3 JSON to v0.4 for a
requested locale. They reject unsafe integers instead of clamping them. The
v0.4 article fixture uses `source_sequence` `9007199254740991` in place of
the v0.3 `9007199254740993`.

## Conformance

Official vectors live at
`conformance/contract/fixtures/vectors/canonical.json`, pinned in
`conformance/contract/VERSION`. Refresh with
`scripts/refresh-ui8kit-contract.sh <commit>`. Do not tighten vendored JSON
Schema (`id` remains `\S` there; Go enforces the Q8 grammar).
